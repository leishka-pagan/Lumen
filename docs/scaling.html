What the calculator assumes

Prices modeled on Claude Haiku 4.5 published rates: $1 / MTok input and $5 / MTok output. Per-alert token budget is a fixed system prompt (~500 tokens), an alert context assembled from source records (~2,000 tokens), and structured claim output capped at 1 to 3 claims (~150 tokens each). The AI-verifies-AI comparison adds one hypothetical verification call per claim: ~3,000 input tokens plus ~100 output tokens each. Verification in Lumen itself is Python code and consumes zero tokens.
FOUR REASONS THE COST IS PREDICTABLE

Why the curve stays flat

A cost is only budgetable if it cannot surprise you. Lumen is designed so it cannot.

1
One call per alert. Full stop.
There is no branching, no retry loop, no agentic tool cascade. The drafter runs once per alert. If it fails, the alert is marked and moves on. The maximum cost of an alert is bounded before it ever starts.
2
Output is capped at 1 to 3 claims
The prompt tells the model to emit no more than three claims per alert, and the tool schema enforces the shape. The upper bound on output tokens is roughly 450 per alert. There is no run-on generation to pay for.
3
Verification is free
Nine Python functions read source rows and return PASS, FAIL, or NEEDS REVIEW. They compile once. They cost nothing to run. Ten thousand verifications per hour cost the same as one: zero tokens.
4
No AI judges AI
Systems that ask a second model to grade the first one double their token cost and turn verification into a probabilistic argument. Lumen refuses that trade. Deterministic code is cheaper, faster, and it always says the same thing about the same data.
